# Как это работает

Одна точка входа `hooks/java-hooks.mjs <Event> --harness claude|gigacode|codex` читает вход
хука из stdin и передаёт его обработчику в `hooks/lib/`. Вне Maven-проекта (нет
`pom.xml`) любой хук молча выходит с кодом 0. Внутренняя ошибка — тоже код 0 (fail open) и
строка в `<tmp>/forbxpg-java/<проект>/<сессия>/hook.log`. В проект хуки ничего не пишут.

## Паспорт проекта

`passport.mjs` читает корневой и модульные `pom.xml`: версии Java и Boot, Lombok,
MapStruct, Liquibase / Flyway, H2, Testcontainers, web-стек, плагины качества, модули,
wrapper, доступность Docker. Кэшируется по mtime и размеру `pom.xml`.

## До записи (PreToolUse)

Для `write_file` / `edit` (GigaCode) и `Write` / `Edit` / `MultiEdit` (Claude) хук строит
файл таким, каким он станет после записи, ищет нарушения в текущем и итоговом тексте и
блокирует только **новые** жёсткие (код 2, сообщение в stderr). Ещё он не даёт править
Liquibase-changeset из `main` (G1), конфиги гейтов (G2) и запускать команды, которые
уничтожают работу или пропускают гейты (S1, S2).

Каждое жёсткое сообщение заканчивается фразой «если пользователь явно просил это —
остановись и спроси…»: модель не повторяет попытку и не обходит блок, решает пользователь
(`disable` в `forbxpg-java.json`). G1 разрешает changelog из `main` расти (новый `include`,
новый changeset в конце) и блокирует только изменение существующих строк. G2 действует на
закоммиченные файлы гейтов; только что созданный агентом `CodeRulesTest` можно исправить.

Почему код 2, а не подсказка: в GigaCode `additionalContext` из PreToolUse до модели не
доходит, а отказ с кодом 2 доходит (проба хуков на GigaCode 26.11.141).

## После записи (PostToolUse)

Новые мягкие замечания этой правки (W1–W12) и, при первом появлении роли в сессии, 3–5
правил роли уходят в `additionalContext`, который приклеивается к результату инструмента —
в самую свежую часть контекста модели.

## Сообщения и сжатие

- GigaCode: каждое сообщение с текстом получает якорь ≤ 60 токенов (паспорт и три
  правила). GigaCode его не дедуплицирует, поэтому он короткий.
- После `PostCompact` (GigaCode) или `SessionStart` с `source: compact` (Claude) следующее
  сообщение один раз получает блок восстановления ≤ 400 токенов.

## Конец хода (Stop)

- Один раз за сессию при `context_usage ≥ 0,70` модель просят записать handoff
  (`grillspec note handoff`, если стоит grillspec, иначе — в начало файла плана).
  `context_usage` присылает только GigaCode; в Claude Code это предупреждение не срабатывает.
- Если сессия меняла `.java` после последней успешной проверки, хук запускает
  `mvnw -q -o compile` (или `mvn`) для затронутых модулей (таймаут 180 с). Блокирует только
  на ошибках в файлах этой сессии, не больше двух раз на один набор изменений; то, что
  проверить нельзя (нет кэша, нет Maven), уходит системным сообщением.

## Правила

Таблица жёстких (J*, G*, S*) и мягких (W*) правил — в [английской версии](../en/how-it-works.md#rules)
и в `hooks/lib/rules.mjs`, где у каждого правила есть текст «что не так / как исправить /
пример».

Правила — построчные регулярки по коду с вычищенными комментариями и строками; всё, что
требует типов, живёт в ArchUnit-гейте (`java-quality-gates`).
