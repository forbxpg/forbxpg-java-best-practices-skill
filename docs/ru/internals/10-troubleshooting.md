# 10. Диагностика

## Хук молчит

Проверьте по порядку.

1. **Открыта новая сессия после установки?** Харнессы читают хуки при старте.
2. **Хуки включены?** GigaCode: нет ли `"disableAllHooks": true` в
   `~/.gigacode/settings.json`. Codex: дано ли доверие в `/hooks`. Claude Code: виден ли
   плагин в `/plugin`, хуки — в `/hooks`.
3. **Есть Node в `PATH`?** Хук — это `node ...`. Без Node харнесс получит ошибку запуска,
   а модель ничего не увидит.
4. **Хук находит Maven-проект?** Нет `pom.xml` ни выше папки сессии, ни в единственной
   подпапке — хук выходит молча. Две Maven-подпапки и нет записи файла — тоже молча.
5. **Проектная установка GigaCode и сессия в подпапке?** GigaCode не читает
   `.gigacode/settings.json` родительской папки. Откройте сессию в корне репозитория.
6. **Правило выключено?** Посмотрите `disable` в `forbxpg-java.json` проекта и
   `~/.forbxpg-java.json`.
7. **Это не новое нарушение?** Хук блокирует только то, что внесла правка. Старое
   нарушение в файле не блокируется.

## Запустить хук руками

Самый быстрый способ понять, что хук ответит. Из корня проекта:

```bash
echo '{"session_id":"debug","cwd":"'"$PWD"'","tool_name":"Write","tool_input":{"file_path":"src/main/java/a/X.java","content":"class X {\n  @Autowired\n  private Object o;\n}\n"}}' \
  | node <путь к хукам>/java-hooks.mjs PreToolUse --harness claude
echo "exit=$?"
```

Ожидается текст `[forbxpg-java] J1: ...` и `exit=2`.

Паспорт:

```bash
echo '{"session_id":"debug","cwd":"'"$PWD"'","source":"startup"}' \
  | node <путь к хукам>/java-hooks.mjs SessionStart --harness gigacode
```

В Windows `cmd` то же самое удобнее через файл: сохранить JSON в `in.json` и выполнить
`node <путь>\java-hooks.mjs PreToolUse --harness gigacode < in.json`, затем
`echo %ERRORLEVEL%`.

Где лежат хуки: плагин Claude Code — папка плагина; расширение GigaCode — папка
репозитория; установка в проект — `.claude/forbxpg-java/hooks/` или
`.gigacode/forbxpg-java/hooks/`.

## hook.log

Внутренние ошибки хука: `<tmp>/forbxpg-java/<12 символов хэша проекта>/<session_id>/hook.log`.
`<tmp>` — `%TEMP%` на Windows, `$TMPDIR` на macOS, обычно `/tmp` на Linux.

- Строка `invalid JSON on stdin` в папке `unknown` — хук вызвали с невалидным входом
  (часто это ручной вызов). Сессия от харнесса всегда приходит с `session_id`.
- Стек исключения — ошибка в коде хука. Хук при этом вышел с кодом 0 и не помешал работе.

## Хук мешает

- **Модель упёрлась в отказ и спрашивает, что делать.** Так и задумано: решает
  пользователь. Либо примите исправление, либо выключите правило для проекта в
  `forbxpg-java.json` (`"disable": ["J1"]`).
- **Stop постоянно сообщает, что сборку проверить не удалось.** Хук компилирует офлайн
  (`-o`). Прогрейте кэш Maven обычной сборкой с сетью. Не хотите компиляцию в конце хода —
  `"stopCompile": false`.
- **Stop блокирует на ошибке, которую модель не может исправить.** Через два блока
  с последней успешной сборки хук отпускает ход с сообщением пользователю.
- **Сборка долгая.** Хук собирает только изменённые модули (`-pl ... -am`) и офлайн. Если
  и это дольше 180 с, хук прекращает сборку и сообщает пользователю.

## Хук ведёт себя не так в другом харнессе

Сравните таблицу [08](08-harnesses.md). Частые причины:

- в Codex Java-правила не блокируют, а приходят после патча;
- в Claude Code нет предупреждения о заполнении контекста: Claude Code не присылает
  `context_usage`;
- якорь по умолчанию только в GigaCode.

## Удаление не вернуло проект как был

`--uninstall` восстанавливает `settings.json` и `GIGACODE.md`, только если после вычистки
своих записей в них не осталось новых чужих настроек. Если команда добавила свои ключи
после установки, они сохранятся, и файл останется. Это намеренно: удаление не трогает
чужое.
