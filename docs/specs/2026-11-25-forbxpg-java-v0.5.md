# Спецификация: forbxpg-java v0.5 — GigaCode «с кайфом»

Статус: **одобрена** 25.11.2026. Дата: 25.11.2026. Продолжает
[спецификацию v0.4](2026-11-25-forbxpg-java-v0.4.md).

## Решения гриля (25.11.2026)

1. Строка состояния — одна строка: общая часть (модель, ветка, контекст) и часть
   forbxpg-java (1а).
2. В строке — результат последней проверки сборки хуком Stop (2а).
3. Ставится отдельным флагом установщика, с резервной копией настроек; чужая настройка
   без `--force` не перезаписывается; удаление возвращает прежнее (3а).
4. Только ASCII (4а).
5. Плюс идеи из обзора чужих строк состояния: полоса контекста с порогами, нарушенные
   правила сессии, время последней сборки, счётчик сжатий, скрытие пустых сегментов,
   предпросмотр без GigaCode, цвета ANSI.
6. Плюс тема forbxpg (светлая и тёмная), баннер, фразы загрузки, команды `/java:*`.
7. Внешний вид (строка, тема, баннер, фразы) — по выбору, одним флагом для всех в
   команде. Команды `/java:*` идут в расширении всегда.
8. Коммиты и PR — без строк об авторстве ИИ.

Допущения (поправьте, если не так):
- фразы загрузки — на русском;
- по умолчанию ставится светлая тема (сейчас у вас Ayu Light), тёмная — флагом `--dark`;
- строка состояния только для GigaCode; для Claude Code — позже, тем же скриптом.

Не входит: свои сочетания клавиш (GigaCode их не настраивает), смена модели, моды
Claude Code, статистика стоимости (GigaCode её не отдаёт).

## 1. Строка состояния

- **R-SL-1.** Команда строки — `node "<клон>/hooks/statusline.mjs"`. Читает JSON из stdin,
  печатает одну строку, всегда выходит с кодом 0. Не запускает процессов (git, Maven):
  только читает файлы, которые пишут хуки. Время работы — в пределах 150 мс на Windows.
  Любая ошибка → строка из одной модели.
- **R-SL-2.** Порядок сегментов через ` · `; сегмент без данных не выводится:
  `<модель> · <ветка> · ctx [######----] 62% · Java 21 · Boot 4.1 · build ok 3m · rules J1 W2 · compact x2 · fj 0.4.3 (0.4.4 available)`.
  Модель, ветка, процент контекста и папка — из stdin GigaCode
  (`model.display_name`, `git.branch`, `context_window.used_percentage`,
  `workspace.current_dir`).
- **R-SL-3. Контекст.** Полоса из 10 знаков `#`/`-` и процент. С `contextWarnAt` из
  настроек (по умолчанию 70%) в конце `!`, с 85% (порог автосжатия GigaCode) — `!!`.
- **R-SL-4. Сборка.** Последний результат Stop в этой сессии: `build ok <N>m` (минут
  назад, `<1m`), `build FAIL` (был блок по ошибке компиляции), `build ?` (не удалось
  проверить). Пока Stop не компилировал — сегмента нет. Stop записывает в состояние
  сессии `lastBuild` = `{ result: ok|fail|unverified, at }`.
- **R-SL-5. Правила.** Id правил, нарушенных в этой сессии, новые первыми, не больше
  четырёх: `rules J1 W2`.
- **R-SL-6. Сжатия.** `compact xN` — сколько раз контекст сжимался в этой сессии
  (новый счётчик `compactions`, растёт в `noteCompaction`).
- **R-SL-7. Обновление.** `fj <установлено> (<новее> available)` — только когда есть
  версия новее. `SessionStart` пишет `<tmp>/forbxpg-java/status.json` =
  `{ installed, latest, at }`; строка читает этот файл и сама remote не ищет.
- **R-SL-8. Сессия.** Если в stdin есть `session_id` — состояние этой сессии; иначе —
  самой свежей по времени изменения сессии этого проекта.
- **R-SL-9. Вне Maven-проекта.** Модель, ветка, контекст и обновление; паспорта, сборки и
  правил нет.
- **R-SL-10. Цвета.** ANSI: жёлтый — `!`, `?`, `available`; красный — `!!`, `FAIL`;
  зелёный — `ok`. Без цвета при `NO_COLOR`. Смысл не держится на цвете: знаки остаются.
- **R-SL-11. Ширина.** Если ширина терминала известна (поле stdin или `COLUMNS`) и строка
  длиннее, сегменты убираются в порядке: `compact`, ветка, `fj`, `rules`, паспорт.
  Модель, контекст и сборка остаются всегда.

## 2. Тема, баннер, фразы

- **R-THEME-1.** Две темы в одной палитре со строкой: `forbxpg Light` и `forbxpg Dark`
  (файлы `gigacode/themes/*.json` в репозитории, все обязательные ключи GigaCode).
  Установщик копирует их в `~/.gigacode/themes/` (GigaCode грузит темы только из
  домашней папки) и ставит `ui.theme` на светлую, с `--dark` — на тёмную.
- **R-BANNER-1.** `ui.customBannerTitle` = `forbxpg-java`, `ui.customBannerSubtitle` =
  `Java · Spring Boot · guarded by hooks`, `ui.customAsciiArt` — логотип из
  `gigacode/banner.txt`: только ASCII, не больше 6 строк по 60 знаков.
- **R-PHRASE-1.** `ui.customWittyPhrases` — 20 фраз про Java и Spring на русском
  (`gigacode/phrases.json`), например «Поднимаю Spring-контекст…».

## 3. Команды `/java:*`

- **R-CMD-1.** В расширении — три команды, файлы `commands/java/*.md`:
  - `/java:review` — загрузить скилл `java-code-review`, взять `git diff` (и `--staged`),
    найти нарушения правил скилла с файлом и строкой;
  - `/java:verify` — загрузить `java-verification`, скомпилировать и прогнать тесты,
    показать вывод сборки как доказательство;
  - `/java:update` — выполнить `node "<расширение>/install.mjs" --check`, показать
    результат и предложить обновление только с «да» пользователя.
- **R-CMD-2.** Тексты команд — обычные инструкции, без подстановок `!{…}` и `{{args}}`:
  так они не просят подтверждения на запуск и одинаково читаются в GigaCode и Claude Code.
- **R-CMD-3.** `install.mjs --scope project` копирует команды в `.gigacode/commands/java/`
  (Claude: `.claude/commands/java/`); удаление установки их убирает.

## 4. Установка внешнего вида

- **R-STYLE-1.** `node install.mjs --gigacode-style [--dark] [--force] [--dry-run]`
  записывает в `~/.gigacode/settings.json` ключи: `ui.statusLine`
  (`type: command`, команда из R-SL-1, `refreshInterval: 5`), `ui.theme`,
  `ui.customBannerTitle`, `ui.customBannerSubtitle`, `ui.customAsciiArt`,
  `ui.customWittyPhrases`. Остальные ключи файла не трогаются.
- **R-STYLE-2.** Перед первой записью — копия `settings.json.forbxpg-java.bak`. Прежние
  значения каждого ключа (или их отсутствие) — в `~/.gigacode/forbxpg-java-style.json`.
- **R-STYLE-3.** Если ключ уже задан не нами, установщик перечисляет такие ключи и
  ничего не пишет; с `--force` — перезаписывает (прежние значения всё равно сохраняются).
  Повторный запуск без изменений ничего не меняет.
- **R-STYLE-4.** `--gigacode-style --uninstall` возвращает каждому ключу прежнее значение
  (или удаляет его) и удаляет файлы тем. Ключи, которые пользователь поменял после
  установки, не трогаются, о них пишется строка.
- **R-STYLE-5.** `settings.json`, который не читается как JSON, не правится: установщик
  останавливается с сообщением.
- **R-STYLE-6.** `--gigacode-style --preview` ничего не меняет и печатает строку состояния
  на тестовых данных в трёх видах (всё хорошо; предупреждения; вне Maven) и баннер.

## 5. Сценарии

- **S-SL-1a.** Сессия в Maven-проекте, контекст 62%, Stop 3 минуты назад скомпилировал,
  нарушены J1 и W2, обновления нет → `<модель> · <ветка> · ctx [######----] 62% · Java 21 · Boot 4.1 · build ok 3m · rules J1 W2`.
- **S-SL-1b.** Контекст 72% → `ctx [#######---] 72% !`; 86% → `… 86% !!`.
- **S-SL-1c.** Stop заблокировал ход ошибкой компиляции → `build FAIL` (красный).
- **S-SL-1d.** Сессия в `C:\Work` без `pom.xml`, есть 0.4.4 → `<модель> · ctx […] 10% · fj 0.4.3 (0.4.4 available)`.
- **S-SL-1e.** Мусор в stdin → строка `?`, код 0.
- **S-SL-1f.** Ширина 60 → остаются модель, контекст и сборка.
- **S-STYLE-1a.** Чистый `settings.json` → шесть ключей записаны, копия и квитанция есть;
  `--uninstall` → файл как до установки.
- **S-STYLE-1b.** В `settings.json` своя `ui.theme` → установщик называет ключ и ничего
  не пишет; с `--force` пишет.
- **S-STYLE-1c.** `--dry-run` и `--preview` не меняют ни одного файла.
- **S-CMD-1a.** `gigacode-extension.json` и проектная установка дают три команды
  `/java:review`, `/java:verify`, `/java:update`.

## 6. Проверить на рабочей машине до релиза

Агент на рабочей машине может прочитать документацию GigaCode, но не может открыть TUI.
Перед релизом — короткая проба:
1. Какие поля приходят в stdin команды строки: есть ли `session_id`, ширина терминала.
2. Пропускает ли GigaCode цвета ANSI из команды строки.
3. Откуда расширение берёт команды: папка `commands/` или поле `commands` манифеста.
4. Формат `ui.customAsciiArt` и работает ли путь темы со слэшами `/`.

По результатам пробы спецификация уточняется до плана исполнения задач 2–3.
