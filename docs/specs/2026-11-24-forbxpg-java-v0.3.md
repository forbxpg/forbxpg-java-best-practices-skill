# Спецификация: forbxpg-java v0.3

Статус: **одобрена** (пользователь, «на автопилоте», 24.11.2026). Продолжает
[спецификацию v0.2](2026-11-24-forbxpg-java-v0.2.md).

## Решения гриля (24.11.2026)

1. В v0.3 входит: адаптивный якорь и английская версия `docs/*/internals`.
2. Правила якоря берутся по порядку: нарушения этой сессии (свежие первыми) → правила
   ролей файлов, которые сессия трогала → три нынешних правила по умолчанию.
3. Паспорт и три правила, ≤ 60 токенов; у каждого правила и роли — короткий текст
   ≤ 40 символов.
4. Нарушения в якоре — три последних **разных** правила (LRU), без таймера.
5. Где якорь включён по умолчанию — без изменений: GigaCode да, Claude Code и Codex нет.
6. Блок восстановления после сжатия получает строку «в этой сессии ты нарушал» — до пяти
   правил с полным «как исправить».
7. Нарушением считается всё, о чём хук сообщил модели (блок до записи или замечание после),
   кроме правил из `disable`.
8. Правило роли пропускается, если его короткий текст повторяет уже взятое правило.
9. Английская версия `internals` — полный перевод, диаграммы с английскими подписями; обе
   версии дальше правятся вместе.

Не входит: Stop при двух Maven-подпапках, живая проверка Codex, проверки организации.

## 1. Короткие тексты правил и ролей

- **R-SHORT-1.** У каждого правила в `RULES` (J1–J6, G1–G2, S1–S2, W1–W12) есть поле
  `short` ≤ 40 символов, у каждой роли из `ROLE_RULES` — короткий текст ≤ 40 символов.
  Тест проверяет длину каждого.
- **R-SHORT-2.** Три правила по умолчанию — текущие тексты якоря:
  `load java-conventions before new classes`, `no @Data on @Entity`,
  `run <compile> before saying done` (`./mvnw -q compile` или `mvn -q compile` по паспорту).

## 2. Учёт нарушений и ролей в сессии

- **R-TRACK-1.** Когда `PreToolUse` блокирует (J, G, S) и когда `PostToolUse` сообщает
  замечание (W, а в Codex и J), хук отмечает id правила в состоянии сессии с меткой времени.
  Повтор того же id обновляет метку. Правила из `disable` не отмечаются — они и не
  сообщаются.
- **R-TRACK-2.** Отметки — по файлу на id правила, параллельные вызовы хука ничего не
  теряют (как маркеры v0.2).
- **R-TRACK-3.** Роли файлов, которые сессия трогала, уже отмечаются в v0.2 (`roles`);
  порядок — по времени первой записи роли, свежие первыми.

## 3. Адаптивный якорь (`UserPromptSubmit`)

- **R-ANCHOR-4.** Якорь — строка паспорта и `Rules: a · b · c`, где три правила выбираются
  так:
  1. короткие тексты нарушенных правил, от последнего к более старым, без повторов;
  2. затем короткие правила ролей, от свежей к более старой;
  3. затем правила по умолчанию;
  4. текст, уже взятый раньше, пропускается.
  - S-ANCHOR-4a: WHEN в сессии ещё ничего не было THEN якорь совпадает с якорем v0.2.
  - S-ANCHOR-4b: WHEN сессия записала сущность и получила W1, а потом сервис получил блок J1
    THEN якорь начинается с J1, затем W1, третье — правило роли `service` (правило роли
    `entity` совпадает по смыслу с W1 и пропускается по тексту, если совпадает).
  - S-ANCHOR-4c: WHEN нарушены четыре разных правила THEN в якоре три последних.
- **R-ANCHOR-5.** Якорь ≤ 60 токенов в худшем случае: самая длинная строка паспорта и три
  самых длинных коротких текста. Проверяет `scripts/check-tokens.mjs`.
- **R-ANCHOR-6.** Включение по умолчанию и ключ `anchor` — без изменений (R-ANCHOR-3 v0.1).

## 4. Блок восстановления

- **R-RECOVER-1.** Если в сессии были нарушения, блок восстановления после списка главных
  правил содержит `Rules you broke in this session:` и до пяти последних разных правил в
  виде `- <id>: <short>. Fix: <fix>`.
  - S-RECOVER-1a: WHEN нарушений не было THEN блок совпадает с блоком v0.2.
- **R-RECOVER-2.** Бюджет блока восстановления поднимается с 400 до **500** токенов: пять
  самых длинных «как исправить» с короткими текстами занимают до ~190 токенов, а блок v0.2
  уже 266. Блок приходит один раз после сжатия, поэтому +100 токенов в худшем случае
  приемлемы (уточнение при написании спецификации, по решению 6).

## 5. Документация

- **R-DOCS-1.** `docs/en/internals/` — те же 11 документов, что `docs/ru/internals/`, на
  английском; диаграммы `docs/en/internals/diagrams/*.mmd` с английскими подписями и PNG
  в `img/`. Ссылки из `README.md` и `docs/en/how-it-works.md`.
- **R-DOCS-2.** Обе версии описывают адаптивный якорь и новую строку блока восстановления;
  таблицы бюджетов — новые лимиты.
